# QuantFM 信号 × 回测框架对接文档

> 版本：v1.3 · 2026-07-24
>
> 生产边界：对外仅交付三列 score 与信号 manifest。

## 1. 一页结论

- 我们交付每日每股一个截面排序分数 `score`，分数越大越看多。
- `score(T)` 使用 T 日全天信息，在 T 日收盘后才可用；最早应在 T+1 执行。
- score 不是预测收益率、概率或仓位，只保证同日截面可排序。
- 回测方负责 PIT 行情、股票池、ST/新股/停牌/涨跌停、成本、冲击、组合与风险。
- 我们内部的 execution panel、未来收益、持仓账本和评估指标不进入生产交付包。

## 2. 交付包

```text
delivery/
├── scores.parquet
└── signal_manifest.json
```

`scores.parquet` 是唯一主数据文件。`signal_manifest.json` 记录：

- 方向：`higher_is_more_bullish`；
- 可用时点：`available_after_signal_date_close`；
- 可比范围：`cross_sectional_within_date`；
- 行数、日期数、最早/最晚日期；
- FM、vocab 和 Ranker artifact 的 SHA-256（提供路径时）。

embedding、panel、checkpoint、Ranker 内部状态、持仓和回测报告不是默认对外交付物。

## 3. `scores.parquet` 严格契约

### 3.1 Schema

| 列 | 类型 | 必填 | 约束 | 示例 |
|---|---|---|---|---|
| `date` | string | 是 | 有效 `YYYY-MM-DD` | `2026-03-02` |
| `symbol` | string | 是 | 6 位数字、左补零、不带交易所后缀 | `000001` |
| `score` | float64 | 是 | 有限值；越大越看多 | `0.8312` |

列名和顺序必须**恰好**为 `date, symbol, score`，不应添加 `market`、`rank`、
`split`、`label`、`fwd_ret` 等列。主键 `(date, symbol)` 必须唯一，不得有 null、NaN 或 Inf。

### 3.2 示例

```text
date,symbol,score
2026-03-02,000001,0.8312
2026-03-02,000002,-0.1204
2026-03-02,600000,0.4510
```

### 3.3 语义

| 项 | 约定 |
|---|---|
| 方向 | 高分更看多，低分更看空 |
| 可比性 | 仅保证同一交易日截面可比 |
| 可用性 | T 日收盘后可用 |
| 建仓 | 最早 T+1，具体价格由回测方冻结 |
| 缺失股 | 视为当日无信号，不要填 0 |
| 数值处理 | 可在同日内做 rank/z-score，不应用未来截面做全期归一化 |

## 4. 回测方最小流程

### 4.1 读取与校验

```python
import polars as pl

from quant_fm.signal.schema import validate_scores

scores = validate_scores(pl.read_parquet("delivery/scores.parquet"))
```

如果对方环境不安装 QuantFM，至少校验列名、日期格式、6 位 symbol、有限值和主键唯一。

### 4.2 对齐 PIT 数据

回测方至少需要：

```text
date | symbol | eligible_at_signal | entry_date | exit_date
entry_px | exit_px | entry_fillable | exit_fillable | ret
```

`date` 是信号日，不是建仓日。建仓和退出日必须通过完整交易日历映射，
不得用某只股票的下一条可见记录代替全市场下一交易日。

### 4.3 信号选股与成交

1. 仅用信号日已知的股票池与 score 生成目标组合。
2. 按 score 从高到低排序，应用 Top-K、缓冲或组合优化规则。
3. 建仓/退出日可成交性只用于成交或拒单。
4. 买入失败不得使用执行日已知信息补选低排名股票，未投资部分保留现金。
5. 按实际成交仓位计算换手、佣金、印花税、滑点和冲击。

仓库内的日频重叠区间模拟在每期 `entry_date` 完成调仓，因此当前买卖只读取
`entry_fillable`；未来 `exit_fillable` 不得提前影响本期目标、持仓或收益。

## 5. 收益时点

我方内部 `ReturnSpec` 使用以下稳定名称，建议对方报告沿用：

| 名称 | 收益区间 | 建议 |
|---|---|---|
| `close_t_close_t1` | T close → T+1 close | 只做旧口径/研究上限，不可执行 |
| `vwap_t_vwap_t1` | T VWAP → T+1 VWAP | 只做旧口径/研究上限，不可执行 |
| `open_t1_close_t1` | T+1 open → T+1 close | 可交易的日内近似 |
| `vwap_t1_vwap_t2` | T+1 VWAP → T+2 VWAP | 当前推荐默认 |

时点图：

```text
T 日盘中/收盘前     score(T) 不可用
T 日收盘后          score(T) 可用
T+1                  建仓/调仓
T+1 → T+2           实现严格默认收益
```

如果联调阶段仍使用 T close → T+1 close，报告必须标注为不可执行的研究上限，
不得作为实盘收益结论。

## 6. 我方内部严格研究实现

内部会将三列 score 与 execution panel 分开，并在交付冻结后才构建未来收益。

### 6.1 构建 execution panel

```bash
uv run python -m quant_fm.downstream.build_panel_from_minio \
  --from-embeddings /path/to/scores.parquet \
  --calendar-file /path/to/calendar_with_future_days.txt \
  --return-spec vwap_t1_vwap_t2 \
  --out /path/to/execution_panel.parquet
```

execution panel 保留信号日的 `eligible_at_signal`、建仓/退出日、价格、
`entry_fillable/exit_fillable` 和 `fwd_ret`。它是研究数据，绝不混入 `scores.parquet`。

### 6.2 运行评估

```bash
make research-score \
  SCORES=/path/to/scores.parquet \
  PANEL=/path/to/execution_panel.parquet \
  OUT_DIR=/path/to/evaluation
```

或使用完整 CLI：

```bash
uv run python -m quant_fm.downstream.run_score_evaluation \
  --scores /path/to/scores.parquet \
  --panel /path/to/execution_panel.parquet \
  --out-dir /path/to/evaluation \
  --factors /path/to/pit_factors.parquet \
  --quantile-groups 10 \
  --top-k-grid 20,50,100,150,200 \
  --rebalance-grid 1,5 \
  --smoothing-grid 1,3 \
  --cost-bps-grid 0,15,30
```

2026 一键入口：

```bash
CALENDAR=/path/to/calendar_with_two_future_days.txt \
RETURN_SPEC=vwap_t1_vwap_t2 \
make research-oos2026
```

输出包含日度 IC、HAC/Newey-West t、block bootstrap、分位收益、组合参数/成本网格、
逐日组合、持仓、成交拒单和输入哈希 manifest。

### 6.3 组合和风险

内部 `simulate_buffered_topk()` 支持 score 历史平滑、入/出排名缓冲、换手上限、成交拒绝、
未投资现金和买/卖/印花税 bps。它比历史简化 `backtest_topk` 更适合 execution panel，
但仍不是生产交易引擎。

可选因子表使用 `date, symbol, factor_*`。`portfolio_exposures()` 计算持仓加权暴露；
`residualize_returns()` 逐日 OLS 生成 `neutralized_ret`，用于中性化 IC。

## 7. Paired OOS 验收

模型 A/B 不应只对比两个均值 IC。必须先固定：

- 同一 `(date, symbol)` 键集合；
- 同一 execution panel 和 return spec；
- 同一股票池、成本、调仓与平滑网格；
- 同一风险因子版本。

当前评估 CLI 一次只处理一份 score，没有 `--paired` 参数。正确方法是对
baseline/candidate 分别运行，再将两份 `daily_ic.parquet` 按日期配对，分析
`candidate_ic - baseline_ic` 的均值、Newey-West t 和移动块 bootstrap 区间，
并对照成本后收益、换手、回撤和暴露。

## 8. 2026-60d 结果的口径

2026 年 60 个信号日最初是晚于 2025 训练期的时序 OOS，但其 score 和回测结果
已经被查看，并用于设计模型底层 v2 改造。因此：

- 该窗口现在是**架构验证/研究窗口**；
- 可作为问题复现、开发回归和 paired 研究比较；
- 不得再称为 v2 的 untouched OOS；
- 最终验收需要一个未被用于任何选型的更晚时间段。

本文不发布任何历史 RankIC 或年化收益数字，避免将已被反复查看的研究数字
误解为新的 OOS 证据。

## 9. 联调验收

| 优先级 | 检查 | 通过标准 |
|---|---|---|
| P0 | 文件与 schema | 可读，列恰好为 `date, symbol, score` |
| P0 | 主键/数值 | `(date, symbol)` 唯一，无 null/NaN/Inf |
| P0 | symbol | 全部为 6 位数字字符串 |
| P0 | 时点 | 未使用 T 日盘中成交假设 |
| P0 | horizon | 完整覆盖最后信号日的 exit 日 |
| P1 | 覆盖 | 与 PIT 股票池/return 的逐日 join coverage 合理 |
| P1 | 执行 | 选股不读后验 fillable，失败不补选 |
| P1 | 相对对照 | 在同口径下与随机/旧模型配对比较 |
| P2 | 稳健性 | HAC、bootstrap、成本网格、风险暴露和新 untouched OOS 都通过 |

## 10. 常见问题

**Q：score 要不要标准化？**

A：没有固定量纲。可在每个交易日截面内做 rank/z-score，但不得使用未来日期拟合归一化。

**Q：没有某只股票的 score 怎么办？**

A：视为当日无信号，不要填 0。

**Q：能否直接把 score 当仓位？**

A：不建议。先用 Top-K 等权和持仓缓冲跑通，再在交易约束下研究 score 加权。

**Q：信号已经行业/市值中性吗？**

A：不做此保证。回测应报告 `factor_*` 暴露，并辅以中性化收益 IC 或约束组合。

**Q：能否做空？**

A：分数方向支持高分多、低分空，但融券池、券源、费率和可成交性由回测方处理。

import polars as pl

s = pl.read_parquet("delivery/scores.parquet")
assert s.columns == ["date", "symbol", "score"]
assert s.height > 0
assert not s.select(["date", "symbol"]).is_duplicated().any()
assert s.select(pl.col("date").str.contains(r"^\d{4}-\d{2}-\d{2}$").all()).item()
assert s.select(pl.col("symbol").str.contains(r"^\d{6}$").all()).item()
assert s.select(pl.col("score").is_finite().all()).item()
print(s.select(pl.len(), pl.col("date").n_unique(), pl.col("symbol").n_unique()))
