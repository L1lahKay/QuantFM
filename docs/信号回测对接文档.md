# QuantFM 信号 × 回测框架对接文档

> **版本**：v1.2 · 2026-07-23 · 生产边界：仅交付 score 信号

---

## 1. 交付物

1. 我们交付的是**日频选股信号表**：每个交易日、每只股票一个分数 `score`。
2. `score` 越大 → 越看多；当天收盘后才可用，**不能**假设盘中已有该分数。
3. 你们用自己的行情、成本、涨跌停规则做回测；我们这边的简易回测**仅供参考，不作验收标准**。
4. 生产交付目录仅包含 `scores.parquet` 与 `signal_manifest.json`；embedding、panel、checkpoint 和研究指标均不对外交付。

---

## 2. 对接关系


| 我们交付                       | 你们负责                     |
| -------------------------- | ------------------------ |
| 日频信号：`date, symbol, score` | 交易日历、可交易股票池              |
| （可选）股日特征向量，供你们自建模型         | 收益标签定义（开/收/VWAP、T+1/T+2） |
| 信号生成时间与版本说明                | 成本、冲击、涨跌停、ST、停牌等约束       |
|                            | 组合构建、净值、风险指标             |


```text
┌─────────────┐         scores.parquet          ┌──────────────────┐
│  信号侧      │  ───────────────────────────►  │  你们的回测框架   │
│ (我们交付)   │   date | symbol | score         │  → 净值 / 指标   │
└─────────────┘                                  └──────────────────┘
```

## 3. 主接口：信号表（必接）



### 3.1 文件格式

- 格式：**Parquet**（优先）或 **CSV（UTF-8）**
- 建议路径约定：

```text
delivery/
  scores.parquet
  signal_manifest.json
```

### 3.2 字段定义


| 字段       | 类型  | 必填  | 含义                                       | 示例           |
| -------- | --- | --- | ---------------------------------------- | ------------ |
| `date`   | 字符串 | 是   | 交易日，格式 `YYYY-MM-DD`                      | `2025-12-12` |
| `symbol` | 字符串 | 是   | 股票代码，**6 位数字、左侧补零**；**不含** `.SH` / `.SZ` | `000001`     |
| `score`  | 浮点数 | 是   | 当日截面打分，**越大越看多**                         | `0.83`       |


**主键**：`(date, symbol)` 唯一，一天一只股票只有一行。

### 3.3 样例

```text
date,symbol,score
2025-12-12,000001,0.8312
2025-12-12,000002,-0.1204
2025-12-12,600000,0.4510
2025-12-13,000001,0.2201
```



### 3.4 语义约定


| 约定     | 说明                                                   |
| ------ | ---------------------------------------------------- |
| 分数方向   | `score` 越高越看多；同日可直接排序                                |
| 可比范围   | **同一交易日**内横截面可比；**不要**跨日直接比绝对值                       |
| 可用时点   | `score(date=T)` 表示用 **T 日全天信息** 算出来的分数，**T 日收盘后**才可用 |
| 建仓时点建议 | 最早在 **T+1** 开盘/竞价/VWAP 建仓（由你们框架定义）                   |
| 空值     | 正常交付中 `score` 不应有 NaN；若出现请丢弃该行并反馈我们                  |
| 股票池    | 信号可能覆盖全市场大部分标的；请先与你们股票池做 `inner join`                |




### 3.5 不要做的假设

- ❌ 不要假设 `score` 是收益率预测（它是排序分数，不是预期收益 %）
- ❌ 不要假设 `score` 已做市值中性 / 行业中性（如需中性，请在你们侧处理）
- ❌ 不要用 `score(T)` 去赚 `T` 日当天的收益（时点不允许）
- ❌ 不要把代码当成 `600000.SH`；统一成 6 位后再对齐

## 4. 你们回测里怎么用（推荐流程）



### 步骤 1：读入信号

```python
import polars as pl  # 或 pandas

scores = pl.read_parquet("delivery/scores.parquet")
# 列: date, symbol, score
```



### 步骤 2：对齐你们的行情 / 收益表

你们至少需要一张表，例如：


| 字段       | 说明                                     |
| -------- | -------------------------------------- |
| `date`   | 与信号日对齐的决策日，或你们定义的成交日（需在文档里写清）          |
| `symbol` | 同样 6 位补零                               |
| `ret`    | 你们定义的可交易收益（如 T+1→T+2 的 VWAP 收益、或收盘到收盘） |


```python
# 伪代码
df = scores.join(your_returns, on=["date", "symbol"], how="inner")
```



### 步骤 3：按日选股

每个交易日：

1. 过滤不可交易标的（涨跌停、停牌、ST、新股等 —— **用你们规则**）
2. 按 `score` **从高到低**排序
3. 取 Top-K（如 50）做多；若做多空，可再取 Bottom-K 做空

```python
# 伪代码：某日
day = df.filter(pl.col("date") == "2025-12-12")
day = day.filter(~pl.col("limit_up") & ~pl.col("suspended"))  # 你们字段
longs = day.sort("score", descending=True).head(50)
```



### 步骤 4：算组合收益并扣成本

- 组合收益：多头等权 / 你们权重方案
- 成本：用你们的佣金、印花税、滑点、冲击模型
- 换仓：相对上一交易日持仓计算换手



### 步骤 5：输出你们标准报告

净值曲线、回撤、换手、持仓明细等 —— **全部由你们框架产出**。

## 5. 时点对齐建议（避免前视偏差）

信号时点固定如下，请在回测配置里写死：

```text
T 日盘中 / 收盘前     ：尚无 score(T)
T 日收盘后           ：score(T) 可用
T+1 日               ：按 score(T) 调仓 / 建仓   ← 建议执行日
T+1 → T+2（或更后）  ：实现收益                 ← 建议收益区间
```

**推荐默认（可讨论）**：


| 项目   | 建议                          |
| ---- | --------------------------- |
| 信号日  | T                           |
| 调仓日  | T+1                         |
| 收益区间 | T+1 成交价 → T+2 成交价（或你们标准持有期） |
| 成交价  | 开盘 / VWAP / 收盘 —— 由你们选定并固定  |


若你们暂时用「收盘价 T → 收盘价 T+1」做联调，请在报告中标注为 **简化假设**，不要当作最终可交易结论。

## 6. 可选接口：特征向量（一般首版不接）

当你们希望**自己训练**下游模型、或把信号当特征融合时才需要。

### 6.1 字段


| 字段                   | 含义                |
| -------------------- | ----------------- |
| `date`               | 交易日               |
| `symbol`             | 6 位代码             |
| `market`             | `SH` / `SZ`（可选）   |
| `emb_0` … `emb_1023` | 1024 维浮点向量（一行一股日） |




### 6.2 说明

- 这是「股票当天的摘要向量」，**不是**买卖分数
- 要得到 `score`，还需你们（或我们）再训一个截面排序模型
- **首版联调建议只接第 3 节的** `score`，复杂度最低

## 7. 联调验收怎么判「通了」

按优先级：


| 优先级 | 检查项       | 通过标准                                   |
| --- | --------- | -------------------------------------- |
| P0  | 文件能读、字段齐全 | 有 `date/symbol/score`                  |
| P0  | 代码能对齐     | 6 位补零后 join 成功率合理                      |
| P0  | 时点正确      | 未使用 T 日盘中成交假设                          |
| P1  | 排序可用      | 每日能稳定选出 Top-K                          |
| P1  | 与随机对照     | 同框架下，信号组合优于随机选股                        |
| P2  | 研究指标      | 日度 RankIC（score 与你们定义的前瞻收益的截面相关）均值显著为正 |


**说明**：当前研究样本为**连续 60 个交易日**（2025-01-02 ~ 2025-04-07），已可给出「可信」的日度指标与一版年化参考；但 3 个月仍偏短、市场状态覆盖有限。联调阶段仍请以「流程跑通 + RankIC/相对随机占优」为主，年化收益只作参考、不作最终拍板依据。

## 8. 我们当前研究侧参考数字

标签口径：`fwd_ret = 次日收盘 / 当日收盘 - 1`，按**全局交易日历**对齐（前瞻恒为 1 交易日）。

下列 RankIC 来自早期稀疏样本（22 个不连续交易日），仅用于证明「信号不是噪声」：

| 训练集 RankIC | ~0.20  |

## 10. 常见问题（FAQ）

**Q1：**`score` **的量纲是什么？要不要标准化？**  
A：无固定量纲。同一天内直接比大小即可。若你们框架要求 z-score / 分位数，可自行转换，但需全样本一致。

**Q2：一天大约多少只股票有信号？**  
A：全市场覆盖时，通常为数千只（与当日可交易池接近）。请以实际文件为准。

**Q3：没有某只股票的分数怎么办？**  
A：视为当日无信号，不要填 0（0 也是一种分数）。直接不参与选股。

**Q4：沪深代码如何区分？**  
A：主接口只用 6 位数字。若你们必须带交易所，请用你们映射表转换；不要反向要求我们改主键格式，除非双方书面约定。

**Q5：信号会每天更新吗？**  
A：研究阶段按批次交付历史区间。若后续要日常增量，另定 SLA（何时点产出次日可用的 `score`）。

**Q6：能不能直接把信号当仓位权重？**  
A：可以，但不推荐首版。建议先 Top-K 等权跑通，再谈 score 加权 / 优化权重。

**Q7：多空是否支持？**  
A：信号本身支持（高分多、低分空）。是否允许做空、融券约束由你们框架决定。
