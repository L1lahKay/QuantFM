## 0.1 数据修订说明（v1.1，必读）

早期联调用的 `medium_300m` panel 是**稀疏采样**（22 个不连续交易日，间隔 10~24 个自然日）。
在这种数据上 `fwd_ret` 的「下一条记录」跨越了很多天，**不具备「次日」意义**，回测的年化/累计
收益都不可解释。本次已修订为**连续交易日**方案：

| 项 | 旧（稀疏，勿用于回测） | 新（连续，回测有效） |
|---|---|---|
| 交易日 | 22 天，跨全年、不连续 | **连续 60 交易日** + 1 天用于末日 fwd_ret（共 61） |
| 交易日文件 | `data/medium_300m_22_dates.txt` | `data/cont_60_dates.txt` |
| `fwd_ret` 对齐 | 按 symbol `shift(-1)`（可能跨多日） | **全局交易日历下一交易日**（horizon 恒为 1 日） |
| `fwd_ret` 口径 | `VWAP(T+1)/VWAP(T)-1` | `close(T+1)/close(T)-1`（次日收盘对收盘） |
| Panel 文件 | `panel/daily_panel.parquet` | `panel/daily_panel_cont60.parquet` |
| 词表 | 预训练拟合 | **复用预训练冻结 `vocab.json`**（`run_medium --reuse-vocab`），保证与模型分箱一致 |

代码改动见 §6（已解决项）与 §12。

## 1. 系统在回测前做了什么

```text
L2 订单流 → tokenize → 预训练 FM
              ↓
        股日 embedding（d_model=1024）
              ↓
        截面 Ranker → score
              ↓
        Top-K 回测（当前为我方简易参考实现）
```

对方若只接「信号」，最小依赖：

```text
date | symbol | score
```

对方若自行训练下游，则需要：

```text
date | symbol | emb_0 … emb_1023
```

## 3. 接口契约

### 3.1 信号表（对方回测主输入）

| 列 | 类型 | 说明 |
|---|---|---|
| `date` | string | `YYYY-MM-DD` |
| `symbol` | string | 6 位股票代码，零填充（如 `000001`） |
| `score` | float | 越高越看多；同日横截面可比 |

来源：`train_ranker.predict()`。回测按日对 `score` 降序取 Top-K。

### 3.2 Embedding 表（对方自训下游时用）

| 列 | 类型 | 说明 |
|---|---|---|
| `date` | string | 交易日 |
| `symbol` | string | 6 位代码 |
| `market` | string | `SH` / `SZ` |
| `emb_0` … `emb_1023` | float | 股日向量，维度 = `d_model` |

约定：

- 一行 = 一个 `(date, symbol)`
- 池化默认 **mean**，按 chunk 事件数加权汇总
- 使用 `best.pt` 抽取；不混用 train/val/test 标签信息

### 3.3 Panel / 标签表（联调用）

当前列：

```text
date, symbol, market, close, pre_close, vwap, upper, lower,
is_st, is_halt, is_new, limit_locked, next_date, fwd_ret
```

当前约定（连续 60 日 panel）：

- `fwd_ret = close(T+1) / close(T) - 1`（**次日收盘对收盘**）
- `next_date` 由**全局交易日历**给出，恒为 T 的下一交易日；停牌/缺数据当日 `fwd_ret=null`
- 信号来自 **T 日全天订单流**，`score(T)` 于 T 收盘后可用；若要更严可交易口径（T+1 建仓 → T+2 实现），对方可平移标签（见第 6 节）

样例规模（`cont60`，`daily_panel_cont60.parquet`）：

- 约 31.2 万行，61 个交易日（60 信号日 + 1 末日），约 5.2k 只标的
- `fwd_ret` 非空约 30.7 万行；空值来自末日、停牌、缺数据
- **交易日间隔校验**：所有非空行 `next_date` 与 `date` 恰好相邻 1 个交易日（横截面 horizon 一致）

### 3.4 参考回测函数

```python
from quant_fm.downstream.backtest_topk import backtest_topk

result = backtest_topk(
    scores,              # date, symbol, score
    panel,               # 至少 date, symbol, fwd_ret；可选 limit_locked
    top_k=50,
    long_short=False,    # True 时做多 Top-K + 做空 Bottom-K
    cost_bps=15.0,       # 按换手收取往返成本（基点）
    min_days=60,         # <60 天不给出年化指标
)
```

输出字段（诚实口径）：

| 字段 | 何时有值 | 含义 |
|---|---|---|
| `n_days` | 始终 | 回测天数 |
| `mean_daily_return` | 始终 | 日均收益 |
| `daily_vol` | 始终 | 日收益波动 |
| `sharpe_daily` | 始终 | 未年化 Sharpe |
| `cum_return` | 始终 | 区间累计收益 |
| `hit_rate` | 始终 | 正收益日占比 |
| `max_drawdown` | 始终 | 最大回撤 |
| `turnover` | 始终 | 平均换手 |
| `sharpe` | 仅 `n_days >= 60` | 年化 Sharpe；否则 `null` |
| `ann_return` | 仅 `n_days >= 60` | 年化收益；否则 `null` |
| `reliable` | 始终 | 年化指标是否可信 |

## 4. 对接 API（契约单页）

本节是回测侧联调的**权威接口说明**：字段必填/可选、Python / CLI 调用、样例代码与校验规则。

### 4.1 两种对接模式

| 模式 | 我方交付 | 对方职责 | 适用场景 |
|---|---|---|---|
| **A. 信号对接（推荐首版）** | `scores.parquet`：`date, symbol, score` | 用自有 PIT 标签做回测 | 最快联通净值 |
| **B. 表征对接** | `embeddings/*.parquet`：`date, symbol, emb_*` | 自训 ranker / 因子融合后再回测 | 对方有独立下游体系 |

可同时交付 A+B；**生产验收以对方回测引擎为准**，我方 `backtest_topk` 仅作参考。

### 4.2 数据 Schema

#### 4.2.1 `scores`（模式 A，必填）

| 列 | 必填 | 类型 | 约束 |
|---|---|---|---|
| `date` | ✅ | Utf8 / string | `YYYY-MM-DD`；与交易日历对齐 |
| `symbol` | ✅ | Utf8 / string | 6 位零填充，如 `000001`；不含 `.SH/.SZ` 后缀 |
| `score` | ✅ | Float32 / Float64 | 有限值；同日越大越看多；**不做标准化假设**（对方可自行 z-score） |

可选扩展列（我方当前不保证产出）：

| 列 | 说明 |
|---|---|
| `market` | `SH` / `SZ` |
| `rank` | 同日截面秩（1=最高分） |
| `split` | `train` / `val` / `test` |

主键：`(date, symbol)` 唯一。  
时效语义：**score(T) 仅在 T 日收盘后可用**，不可用于 T 日盘中成交假设。

#### 4.2.2 `embeddings`（模式 B）

| 列 | 必填 | 类型 | 约束 |
|---|---|---|---|
| `date` | ✅ | string | `YYYY-MM-DD` |
| `symbol` | ✅ | string | 6 位零填充 |
| `market` | 建议 | string | `SH` / `SZ` |
| `emb_0` … `emb_{D-1}` | ✅ | float | `D = d_model`；302M 为 **1024** |

约束：

- 一行一股日；无 NaN/Inf
- 与 checkpoint 的 `d_model` 一致
- train / val / test 文件可分可合（`all.parquet` 为合并件）

#### 4.2.3 `panel`（联调标签；对方正式环境可替换）

| 列 | 必填（联调） | 类型 | 说明 |
|---|---|---|---|
| `date` | ✅ | string | 信号日 T |
| `symbol` | ✅ | string | 6 位 |
| `fwd_ret` | ✅ | float / null | 前瞻收益；null 行应丢弃 |
| `limit_locked` | 建议 | bool | True = 涨跌停锁死，不可建仓 |
| `is_halt` | 建议 | bool | 停牌 |
| `is_st` | 建议 | bool | ST（当前我方恒 False，需对方覆盖） |
| `is_new` | 建议 | bool | 新股（当前我方恒 False，需对方覆盖） |
| `close` / `vwap` / `pre_close` | 可选 | float | 排查用 |
| `next_date` | 可选 | string | 对齐到的下一记录日（审计用） |

当前 `fwd_ret` 定义（连续 60 日 panel）：`close(T+1)/close(T)-1`，`next_date` 为**全局交易日历**的下一交易日（horizon 恒为 1 日）。正式环境可按第 6 节口径进一步替换为 T+1→T+2 等。

### 4.3 文件交付约定

```text
quant_fm/runs/medium_300m/
├── embeddings/
│   ├── train.parquet
│   ├── val.parquet
```

#### 4.4.2 参考回测

```python
from quant_fm.downstream.backtest_topk import backtest_topk

bt = backtest_topk(
    scores,
    panel,
    top_k=50,
    long_short=False,
    cost_bps=15.0,
    min_days=60,
)
print(bt.as_dict())
# 关注: cum_return, sharpe_daily, hit_rate, max_drawdown, turnover, reliable
# 短样本时 sharpe / ann_return 为 None
```

签名：

```python
def backtest_topk(
    scores: pl.DataFrame,   # date, symbol, score
    panel: pl.DataFrame,    # date, symbol, fwd_ret [, limit_locked]
    *,
    top_k: int = 50,
    long_short: bool = False,
    cost_bps: float = 15.0,
    min_days: int = 60,
    trading_days: int = 244,
) -> BacktestResult: ...
```

执行假设（参考实现）：

1. 按 `date` 分组，对 `score` 降序
2. 多头 = Top-K；`long_short=True` 时空头 = Bottom-K（等权美元中性）
3. 若存在 `limit_locked`，过滤锁死标的
4. 日收益 = 组合 `fwd_ret` 均值 − `turnover * cost_bps / 1e4`
5. `n_days < min_days` → 不年化

### 4.6 对方回测最小接入伪代码

```python
import polars as pl

scores = pl.read_parquet("scores/test.parquet")
# 对方自有 PIT 收益表，至少: date, symbol, ret
rets = pl.read_parquet("pit_returns.parquet")

df = scores.join(rets, on=["date", "symbol"], how="inner")
# 可选: 过滤 ST / 停牌 / 涨跌停 / 新股

daily = []
for (date,), sub in df.group_by("date", maintain_order=True):
    longs = sub.sort("score", descending=True).head(50)
    # 用对方定义的可交易收益列，例如 ret_t1_t2
    daily.append({"date": date, "pnl": floats(longs["ret"].mean())})

# 对方引擎继续: 成本、冲击、净值、年化……
```

### 4.7 校验清单（联调 gate）

对方收到文件后建议先跑：

| # | 检查 | 通过条件 |
|---|---|---|
| 1 | schema | 含 `date, symbol, score`（或 `emb_*`） |
| 2 | 主键唯一 | `(date, symbol)` 无重复 |
| 3 | symbol 格式 | 全为 6 位数字字符串 |
| 4 | 有限值 | `score` / `emb_*` 无 NaN/Inf |
| 5 | 覆盖率 | 与对方股票池按日 inner join 后，日均标的数合理（千级） |
| 6 | 时效 | 明确 `score(T)` 只能用于 T 收盘后决策 |
| 7 | 基线 | 同口径 RankIC 显著高于随机（当前 test 随机约 0.002） |

### 4.8 错误与空值约定

| 情况 | 约定 |
|---|---|
| `fwd_ret` 为 null | 该行不参与 IC / 回测 |
| 某日可交易标的 < 20 | 我方 `build_features` 丢弃该日 |
| `limit_locked=True` | 参考回测剔除；对方应用自有规则 |
| 短样本 `<60` 日 | 年化字段为 `null`，`reliable=false`；勿强行年化 |
| symbol 对不齐 | 统一零填充 6 位后再 join；不要带交易所后缀 |

- 该样本 22–23 个不连续交易日，`fwd_ret` 无「次日」意义，年化/累计 PnL 不可解释。

### 5.2 连续 60 日样本（`cont60`，回测有效口径）

- Panel 已生成并通过交易日历校验（§0.1 / §3.3）。
- Embedding 抽取 + Ranker + Judge 正在连续数据上重跑；RankIC / ICIR / CPCV / 回测数字**待回填**。
- 连续 60 日已达 `min_days=60` 门槛，届时年化 Sharpe / 回撤将首次成为「可信」口径（`reliable=true`）。

## 6. 已知问题（对接前必须对齐）

### ✅ 本次已解决（v1.1）

- **`shift(-1)` 跨多日问题 → 已修复**：`attach_fwd_ret` 改为按**全局交易日历下一交易日**对齐
  （`build_panel_from_minio.py`）。所有行 horizon 恒为 1 交易日；停牌/缺数据当日 `fwd_ret=null`，
  不再把多日收益误当次日。已用连续 panel 校验通过（间隔全部 = 1）。
- **样本太短 → 已缓解**：连续 60 交易日 ≥ `min_days=60`，年化指标首次可信（`reliable=true`）。
- **VWAP(T) 分母的强前视 → 已缓解**：连续 panel 默认 `close(T+1)/close(T)-1`，为标准次日收益。

### ⚠️ 仍需对齐

按优先级：

1. **收盘执行的边界前视**  
   `close(T)→close(T+1)` 假设 T 收盘即可按收盘价建仓（借收盘竞价，近似但略乐观）。更严口径为
   `VWAP(T+2)/VWAP(T+1)`（T+1 建仓 → T+2 实现）；对方可在自有标签里平移一日。

2. **ST / 新股未真正过滤**  
   `is_st` / `is_new` 目前恒为 `False`；正式回测需对方日历覆盖。

3. **多头未市场中性**  
   RankIC 使用原始 `fwd_ret`；多头 PnL 含 beta。更干净的口径是 long-short，或对收益做横截面去均值。

4. **成本模型极简**  
   固定 15bps × 换手；无印花税分档、滑点、冲击、T+1 卖出约束细化。

5. **窗口仍偏短**  
   60 交易日约 3 个月，够给出「可信」日度指标与一版年化，但跨市场状态（牛/熊/震荡）覆盖有限，
   后续可继续扩到半年 / 一年。

**复现命令**

```bash
# 1) 连续 panel（次日 close/close，全局交易日历对齐）
uv run python -m quant_fm.downstream.build_panel_from_minio \
  --dates-file quant_fm/data/cont_60_dates.txt \
  --price close \
  --out quant_fm/runs/cont60/panel/daily_panel_cont60.parquet

# 2) 连续 60 日全市场 tokens（复用冻结 vocab；断点续跑）
uv run python -m quant_fm.scripts.run_medium \
  --dates-file quant_fm/data/cont_60_dates.txt \
  --workdir quant_fm/runs/cont60 \
  --reuse-vocab quant_fm/runs/medium_300m/data/vocab.json \
  --drop-clean --drop-events --resume

# 3) 抽 embedding（bf16 多卡）→ 4) judge（用连续 panel）
NPROC=8 DTYPE=bf16 SPLIT=test bash quant_fm/scripts/extract_embeddings_parallel.sh   # 对 cont60 manifest
uv run python -m quant_fm.downstream.run_judge \
  --workdir quant_fm/runs/cont60 \
  --checkpoint quant_fm/runs/medium_300m/run/best.pt \
  --panel quant_fm/runs/cont60/panel/daily_panel_cont60.parquet \
  --emb-dir quant_fm/runs/cont60/embeddings \
  --epochs 30 --device cuda:0 --top-k 50 --seed 42
```

> 注：embedding 用预训练 `best.pt` 抽取，但 tokens 走 `cont60` 自己的 `manifest.json`（复用冻结 vocab）。
