# Dense230M V1 与 Backbone-MoE V1 完整对比报告

> 报告日期：2026-08-11  
> 对比对象：`dense_230m_v1` 与 `backbone_moe_v1`  
> 结论范围：V1 数据上的单次同预算预训练对照，不代表 V2 结论，也不是与历史 302M 模型的对比。

## 一、结论

本次实验在同一数据、同一训练预算、同一验证窗口和同一随机种子下，完成了 Dense230M 与 Backbone-MoE 的结构对照。主要结论如下：

1. **MoE 在本次实验中没有带来预训练效果改善。** Dense 的最佳验证损失为 `5.81305394`，MoE 为 `5.81594505`。该指标越低越好，MoE 高 `0.00289111`，相对高约 `0.05%`。
2. **MoE 使用了更多参数和存储。** 参数量从 `231.52M` 增加到 `297.59M`，增加 `66.08M`，增幅为 `28.54%`；模型文件大小也基本同比例增加。
3. **运行记录显示 MoE 本次训练用时更长。** 按 TensorBoard 首尾时间粗略计算，Dense 约 `27小时13分`，MoE 约 `36小时05分`，MoE 多用约 `8小时53分`。该口径包含验证和 checkpoint 保存，且两次训练不在同一日运行，只能用作本次实际运行成本参考，不能代替受控性能基准。

## 二、Dense 和 MoE 具体指什么

### Dense230M

Dense 模型中，每个事件 Token 都经过同一组网络参数。它的优点是结构直接、路径稳定、训练和推理容易控制。本次 Dense 模型为 18 层、1024 维、16 个注意力头，所有层都使用普通 Dense FFN。

### Backbone-MoE

MoE（Mixture of Experts，混合专家）希望让不同专家分别处理不同类型的市场事件。本次对比的是 **Backbone-MoE**，不是 Temporal Regime-MoE：

- 底部 14 层与 Dense 相同；
- 顶部 4 层改为“1 个共享专家 + 4 个路由专家”；
- 共享专家始终工作，每个 Token 再由 Router 选择 1 个路由专家；
- 单个 Token 实际激活的 FFN 宽度为 `1024 + 1792 = 2816`，与 Dense 的 2816 对齐。

因此，这是一次**理论激活宽度接近、但总参数量不相等**的对照。MoE 中未被选中的路由专家虽然不参与当前 Token 的主计算，但仍然占用参数、存储和分布式管理成本，Router 也会引入额外的分派开销。

## 十、当前能下什么结论

### 可以明确下结论

1. 两个模型都完成了 8 卡、50,000 updates 和 128.75 亿有效 Token 的 V1 预训练。
2. 在同一份验证计划上，MoE 的主预测损失未优于 Dense。
3. MoE 总参数、checkpoint 存储和本次实际运行时间都高于 Dense。
4. Dense 已形成下游信号产物，且显示一定排序信息，但扣费后的独立策略仍未通过。
5. 基于现有证据，Dense 是更合理的后续对照基准。

### 不能下的结论

1. 不能说 MoE 在所有数据、所有随机种子或 V2 任务上都不如 Dense。
2. 不能说 Dense 的 RankIC 和收益优于 MoE，因为 MoE 根本没有同口径的下游结果。
3. 不能确认 MoE 已学习到稳定、有意义的专家分工，因为路由健康数据未留存。
4. 不能将这次结果当作 V2 Token、真实因果盘口或新 Loss 的效果。
5. 不能将单随机种子、单验证交易日的 `0.05%` 差距解读为稳定的统计显著性。

## 十一、后续验证方案

如果继续评估 MoE，建议不直接重跑大规模 230M，而是按以下顺序缩小决策成本：

1. **先冻结数据和口径。** 使用同一份正式 FULL V2 数据、相同 Token/Loss、相同 validation windows 和一段全新 untouched OOS。
2. **先做小规模多种子。** 在 25M 或 100M 规模下，Dense 和 MoE 至少各跑 3 个随机种子，不同时更改 Tokenizer、Loss 和模型结构。
3. **同时做两种公平预算。** 一组固定有效 Token 数，另一组固定总墙钟或 GPU 小时，避免“参数多但跑得慢”被忽略。
4. **补齐路由和资源证据。** 记录每层专家占比、路由熵、Top-1 置信度、overflow、non-pad tokens/s、峰值显存和 checkpoint 恢复。
5. **对齐下游评估。** 使用同一版 Ranker、同一个时点正确的 T+1/T+2 标签、同一股票池、成本和风险约束，一次性比较 RankIC、ICIR、换手和扣费结果。
6. **设置明确晋级门槛。** 例如：至少 2/3 个随机种子的下游增益为正，平均 `ΔRankIC ≥ 0.005`；专家无明显塌缩；如果吞吐下降超过 10%，必须有更高且稳定的下游增益进行补偿。
