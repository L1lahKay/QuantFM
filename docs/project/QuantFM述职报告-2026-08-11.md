## 一、工作概述

在实习期间我主要围绕数据生产、模型训练、信号交付和训练环境四条主线推进 QuantFM。核心目标是把原始逐笔行情、训练数据、模型产物和日频选股信号连接成一条可重复运行、可检查、可持续迭代的完整链路。

目前，项目已经具备三项核心能力：一是能够稳定生产全市场训练数据；二是能够完成数亿参数模型的多卡训练并保留完整模型产物；三是能够按照统一格式批量交付股日评分。

目前基于V1架构完成训练的模型产出的交易信号具有不错的横截面排序价值，但尚未稳定获得收益。因此迭代出了V2架构，V2架构已完成编排，但尚未完成正式规模训练和全新样本外验证。

### 1. 完成数亿参数模型训练

在模型训练方面，我完成了从小规模验证到数亿参数模型的分阶段训练。其中，V1 300M和Dense 230M 已完成 8 卡正式训练，累计完成 50,000 次更新和约 128.75 亿个有效训练 token，并产出了用于评估、推理和恢复训练的完整模型文件。

同时，我在相同数据和训练预算下完成了 Dense 与 MoE 方案的对照。MoE 的参数量增加约 28.5%，但验证结果没有优于 Dense。基于这一结果，我没有继续盲目扩大复杂模型投入，而是将 Dense 保留为后续实验基准。

### 2. 将模型结果转化为标准化信号交付

我完成了从模型表征到日频选股评分的交付闭环，最终信号统一为 `date、symbol、score` 三个字段。

本次共交付 61 个交易日、60,846 条 score，覆盖 1,000 只股票；没有缺失日期、无效代码、空值或重复记录。

### 3. 完成效果复核

对信号的排序能力、组合收益、换手和交易成本进行了完整复核。

Dense230M 在 59 个可计算交易日上的平均 RankIC 为 0.0725，其中 64.41% 的日期为正，说明信号持续包含一定的横截面排序信息。固定组合累计毛收益为 0.16%，证明这些信号需要合适的组合优化方案。

与历史 302M 模型相比，Dense230M 的排序指标差异不明显，V2模型尚未完成训练，因此现阶段没有证据证明单纯扩大或更换模型结构能够直接提升业务结果。

### 4. 建成支撑模型迭代的规模化数据生产链路

围绕原始数据体量大、单次处理时间长、任务中断后容易返工等问题，我完成了从原始逐笔行情读取、订单簿回放到训练样本生成的完整流程，并加入按日并行、断点续跑、过程监控和本地缓存能力。

经过流程优化，处理效率提升至原来的 2.13 倍。更重要的是，数据生产从一次性脚本变成了可恢复、可查询进度、可增量扩展的稳定流程，为后续模型训练和信号迭代降低了成本。

### 5. 完成 V2 框架升级和验证体系建设

针对 V1 在数据表达、因果边界、版本管理和实验可比性方面的不足，我完成了 V2 的核心工程升级。新版本加强了事件前后状态区分、训练过程监控、模型产物追溯和严格样本外入口，降低了数据混用、未来信息泄漏和实验不可复现的风险。

目前 V2 的代码框架、数据入口、实验配置和验收机制已经形成，并具备从小规模实验逐步放大的条件；但正式全市场数据、规模训练和全新样本外收益结论尚未完成。

## 四、当前问题

1. **训练数据覆盖的市场状态仍然有限。** 当前模型虽然处理了大量事件，但独立交易日数量不够多，不能仅凭事件总量判断泛化能力。
2. **信号尚未稳定覆盖交易成本。** 当前信号的组内排序能力强，但换手和成本对收益影响明显，需要结合合适的组合优化方案使用。
3. **V2 仍处于正式训练前阶段。** 代码和验收框架已完成，真实数据质量、重复实验和全新样本外效果仍是决定是否放大的关键。
4. **GPU限制了训练规模和迭代速度。** 现有环境虽然有单节点 8 张 GPU，但共享训练配额最多可使用 4 张，单卡显存约 32GB，正式 8 卡和多节点任务暂时无法在共享调度环境执行。这不影响已经完成的 Dense230M 训练结论，但会限制 V2 更大规模训练的批量和并行度，拉长多次重复实验与方案验证周期。
5. **CPU 和硬盘制约数据清洗速度。** 逐笔数据清洗需要进行大量订单簿回放和中间文件读写，CPU 核数直接决定可并行处理的股票和交易日数量，硬盘容量与读写速度则影响原始数据缓存、中间结果落盘和训练数据生成。现有流程经过优化后已达到每小时处理 16.3 个交易日，但进一步扩大日期范围、股票范围或同时开展多组实验时，仍会受到 CPU 并发能力和单节点磁盘 I/O 的限制，延长数据准备时间，并进一步推迟模型训练和效果验证周期。

## 五、下一阶段计划

1. 完成至少 5 个真实交易日的 V2 数据试点，先通过数据质量和因果一致性检查，再冻结训练版本。
2. 统一股票池、执行标签、交易成本和风险控制口径，按新口径重训 Ranker，并与简单因子和不使用预训练表征的模型进行公平对照。
3. 先在小模型上完成多次重复实验，把稳定有效的方案放大到更大模型，控制试错成本。
4. 预留一段从未参与方案选择的新样本外窗口，在方案冻结后一次性检验排序能力、扣费收益、风险暴露和容量。
5. 将现有 score 接入多因子体系，验证其在行业、风格和换手约束下能否提供稳定的增量贡献。
6. 如果QuantFM投入实盘使用的话，为了保证效果，要么增加硬件资源量，要么把当前的全市场全量订单训练框架修改成特定指数股的抽样订单训练。
