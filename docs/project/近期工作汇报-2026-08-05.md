# QuantFM 近期工作汇报

> 时间：2026-07-15 至 2026-08-05  
> 汇报人：Khalil

这段时间主要在推进数据处理、模型训练、信号交付和 GPU 训练环境。V1 从原始逐笔数据到最终 score 已经跑通，现有信号能提供一定的横截面区分度，可以作为选股模型的增量因子使用；但扣费后的独立策略收益还不稳定，暂时不能把它当成已经验证完成的交易策略。V2 和 MoE 的代码已基本补齐，但正式的 V2 数据和训练还没有完成。

## 1. 数据处理和模型训练

已打通 MinIO 取数、订单簿回放、events/tokens 生成和多卡训练。当前处理的全市场数据包含：

- 22 个交易日；
- 5,105 只股票；
- 111,692 个 token 分片；
- 7,283,472,495 条事件，约 72.83 亿条；
- token 文件约 39 GB。

数据处理增加了按日并行、断点续跑、单次读取和本地缓存。64 核环境下，处理速度从 7.7 天/小时提升到 16.3 天/小时，实测提速 2.13 倍。

Dense230M V1 已完成 8 卡 FSDP 训练：

| 项目 | 结果 |
|---|---:|
| 参数量 | 231.52M |
| Optimizer update | 50,000 |
| Non-pad token | 12,875,096,787 |
| Best validation loss | 5.81305394 |
| Checkpoint | `best.pt`、`final.pt`、`final_resume.pt` 均已生成 |

同时跑完了同数据、同验证窗口和同训练预算的 Backbone-MoE V1。该模型有 297.59M 参数，best validation loss 为 5.81594505。与 Dense 相比，参数多了 28.5%，validation loss 高约 0.05%。现有结果看不出 MoE 的优势，后续会先保留 Dense 作为对照。

Dense230M 使用的是另一套连续日期数据，实际包含 28 个训练日、1 个验证日和 32 个测试日。虽然有效 token 已达到 128.75 亿，但独立交易日和市场状态仍然偏少。当前训练验收中，运行健康和 checkpoint 恢复已经通过，预训练材料已准备完成；下游价值验证以及 V2/MoE 是否继续放大仍处于待验证状态。

## 2. 2026 年信号交付

这次交付的是标准化股日 score，主表只有三列：

```text
date | symbol | score
```

`score` 越大表示当日横截面上越看多。
`score(T)` 在 T 日收盘后可用，最早用于 T+1 交易。某只股票当日没有 score 时，不应补成 0。

### 数据范围

| 数据 | 行数 | 日期 | 其他 |
|---|---:|---|---:|
| 训练 embedding | 310,636 | 2025-01-02 至 2025-04-07 | 1,024 维 |
| 训练 panel | 312,314 | 2025-01-02 至 2025-04-07 | 主键覆盖率 100% |
| OOS embedding/score | 60,846 | 2026-01-05 至 2026-04-08 | 1,024 维 |

Ranker 的训练截止日是 `2025-04-03`，标签信息最晚到 `2025-04-07`。OOS 打分从 `2026-01-05` 开始，时间上晚于训练数据和标签数据。打分阶段只读取 embedding，不读取未来收益列。

从日期切分和打分输入看，没有发现训练期与 2026 年 OOS 直接重叠。不过，现有 Ranker 使用的是历史标签口径，即 T 日 VWAP 到 T+1 日 VWAP 的收益，而 score 要到 T 日收盘后才能生成。这个标签和真实可执行时点并不完全一致。当前代码已经把严格口径改为 T+1 VWAP 进入、T+2 VWAP 退出，但已有 Ranker 还没有按新口径重训。后续正式实验需要统一用新的执行标签，不能把旧标签下的结果直接当成可交易收益。

训练 panel 中有 5,261 行 `fwd_ret` 为空，训练时直接跳过。有效标签覆盖率为 98.33%，高于当前 95% 的最低要求。

### 换手情况

- 相邻交易日的共同股票覆盖率平均为 99.92%；
- 股票百分位排名日均变化 15.08%；
- Top-50 平均单日换手率为 51.27%，最高为 80%。

股票覆盖范围比较稳定，但头部排名变化不小。所以这批 score 已经可以交给回测端，但现在还不能据此说有稳定收益。下面补充了 RankIC 和固定组合的扣费复核，容量、完整风险暴露和更真实的成交约束仍需继续验证。

### 信号效果复核

在现有 score 上补做了一次统一口径的只读复核：T 日收盘后生成 score，T+1 VWAP 进入，T+2 VWAP 退出；本地能完整取得 T+2 数据的日期共有 59 个。为了避免只看最优参数，主组合在复核前固定为候选池 350 只、持仓 300 只、每 3 日调仓、3 日平滑、单次换手上限 15%，买卖两侧各计 15bp 成本。

| 指标 | 历史 302M V1 | Dense230M V1 |
|---|---:|---:|
| 平均 RankIC | 0.0740 | 0.0725 |
| ICIR | 0.565 | 0.541 |
| RankIC 为正的日期占比 | 83.05% | 64.41% |
| HAC t 值 | 3.61 | 3.72 |
| 5 日块 bootstrap 95% 区间 | [0.0425, 0.1213] | [0.0397, 0.1143] |
| 主组合累计毛收益 | 0.37% | 0.16% |
| 主组合累计净收益 | -0.42% | -0.60% |
| 日均换手率 | 4.45% | 4.33% |
| 累计交易成本 | 0.79% | 0.77% |
| 最大回撤 | -7.61% | -8.94% |

这组结果说明两件事：第一，在这次复核中，两个模型都表现出了一定的横截面排序信息；第二，这种排序信息还没有自然转化为稳定的扣费收益，当前固定组合的毛收益被交易成本基本吃掉。

Dense230M 的头部区分度仍有一定价值：Top-50、Top-300 和 Top-350 相对当日可评分股票的日均收益差分别约为 8.41bp、9.44bp 和 9.81bp。两个模型相对可评分股票等权基准的按日主动收益直接相加，均约为 0.57 个百分点。不过，Dense230M 与历史 302M 的日度 RankIC 差值为 -0.0015，bootstrap 95% 区间为 [-0.0268, 0.0241]，目前没有证据说明 Dense230M 明显优于历史模型。

参数敏感性也比较明显。同一窗口内，Dense230M 的部分组合净收益可以达到 1.36%，但其他组合最低约为 -3.69%。由于这些参数已经在同一段 2026 年数据上看过，不能再挑出其中最好的结果当作样本外结论。现阶段更稳妥的定位，是把这类 score 作为已有选股框架中的增量因子，检验它能否在控制行业、风格和换手后提供额外收益，而不是单独依赖它构建策略。

这次复核仍有边界：股票池不是正式的时点可得成分股文件，ST、新股、涨跌停、冲击成本和容量处理还不完整，因此以上数据用于判断信号方向和暴露问题，不作为实盘收益承诺。

另外，2026 年这批数据后来已经用于分析 V1 问题和设计 V2 方案。它可以继续用来做开发对比，但不再作为 V2 最终测试集。

## 3. V2 Token、Loss 和 MoE 设计

V2 部分已完成因果盘口、Tokenizer V2、字段融合、Loss、分层池化和跨股票上下文。事件排序改为交易所时间和交易所序号，订单簿会同时保留事件发生前后的状态；embedding 也增加了重叠因果窗口和不同时间尺度的池化，目的是减少整日平均对短时信号的稀释。25M、100M 和 230M 三档 Dense 配置已经准备好，但还没有跑正式 V2 训练。

### Token 设计

V2 仍按字段编码事件。事件类型、方向、价格和成交量各自使用独立词表，没有拼成组合 token。组合词表在逐笔数据上会很快膨胀，低频组合过多，跨股票复用也差。股票代码和绝对价格不进入 token，模型需要从订单流结构中提取信息，股票身份和价格区间都是噪声。

输入字段做了收缩。`event_source` 与事件类型重复度较高，`order_type` 含有规则推断值，`board` 日内基本不变，这些字段不再进入主预测目标。`session` 保留为输入，用于区分交易阶段，但不计算预测 Loss。

V1 对缺失值的处理不够严格，部分字段会先填 0 再分箱，真实的零值和缺失值混在一起。V2 分开定义 `PAD`、`UNK` 和 `NA`：`PAD` 只用于补齐序列，`UNK` 表示词表外类别，`NA` 表示当前事件没有该字段。

价格、成交量和时间间隔等连续字段同时保留分箱 token 与标准化 scalar。token 提供稳定的离散表示，scalar 补充分箱内部的数值差异。

盘口特征按事件前后分开记录。下一事件预测可以读取当前事件结束后的盘口；描述当前事件价格位置时，只使用事件发生前的 midpoint，避免当前事件通过 post-state 泄漏到自身特征。新增的 9 个盘口字段暂时只作为输入，是否增加相应预测头留给后续消融实验决定。

分箱边界通过完整训练流上的确定性分层采样拟合，重复分位点会直接合并。artifact 同时记录 occupancy、缺失率、UNK 比例和训练熵，用于检查无效字段和后续数据漂移。

### Loss 设计

V1 的总 Loss 是 6 个字段交叉熵之和。这个口径受字段熵和类别数影响很大：高熵字段天然数值更高，`session` 一类容易任务又会很快收敛，因此总 Loss 的下降不一定代表关键字段同步改善。

V2 用 `TargetSpec` 固定每个目标的权重、适用事件、忽略值和 Loss 类型。字段交叉熵先除以训练集熵，再进入加权求和，使不同难度任务的数值处于更可比的尺度。当前配置如下：

| 目标 | 主 Loss 权重 | 有序距离权重 |
|---|---:|---:|
| 事件类型 | 1.00 | 0 |
| 买卖方向 | 1.00 | 0 |
| 价格分箱 | 1.00 | 0.50 |
| 成交量分箱 | 0.50 | 0.25 |
| 时间间隔分箱 | 0.50 | 0.25 |
| Session | 不预测 | — |

价格、成交量和时间间隔的 bin 具有顺序。普通交叉熵无法区分相邻档位和远距离错误，因此这三类目标额外加入 ordinal SmoothL1。`NA`、padding 以及不适用于当前事件的目标通过 mask 排除；某项在一个 batch 中没有有效样本时返回可反向传播的零值，避免产生 NaN。

FM 与 Ranker 使用两套目标。FM 只做下一事件预测，未来收益不会进入 Tokenizer 或预训练主干。FM 冻结后，Ranker 使用 Multi-K LambdaNDCG、全截面 IC 和 Huber 辅助回归训练，权重为 `1.0 × LambdaNDCG + 0.30 × IC + 0.05 × Huber`。排序重点放在 Top-50、Top-300 和 Top-350，与当前选股组合的截断位置一致。

### MoE 架构

MoE 目前是候选实验，不是 V2 的默认结构。代码中保留两条路线：

| 方案 | 路由位置 | 路由依据 | 当前设置 | 主要用途 |
|---|---|---|---|---|
| Temporal Regime-MoE | 股日或日内聚合之后 | 当时可用的市场、行业和流动性状态 | 1 个共享专家、4 个路由专家、Top-2 | 让同一套订单流表征适应不同市场状态 |
| Backbone-MoE | Transformer 顶部 4 层 FFN | 每个事件 token 的 hidden state | 1 个共享专家、4 个路由专家、Top-1 | 让不同专家处理不同事件、时段或流动性模式 |

Temporal Regime-MoE 直接接在已训练的 Dense FM 后面，改动和计算成本较小，适合先验证。Backbone-MoE 改动预训练主干，需要重新训练；router 依据事件 hidden state 分配专家，不能事先把某个专家定义为“牛市”或“熊市”专家。

两种结构都保留共享专家，用于承接通用订单流模式。路由专家只处理增量部分，router 尚未稳定时仍有公共计算路径。Backbone-MoE 只替换顶部 4 层 FFN，底层继续学习通用事件表示；每个 token 的 active FFN 宽度维持 2,816，与 Dense230M 的实际计算宽度对齐。

Router 的负载均衡 Loss 和 z-loss 权重分别为 0.01 和 0.001，作用是控制专家使用失衡和 logits 数值，不用于衡量主任务效果。评估时需要同时记录专家占比、路由熵、overflow、吞吐、显存以及多 seed 样本外结果。

现有 V1 同预算对照中，Backbone-MoE 参数量由 231.52M 增至 297.59M，validation loss 为 5.81594505，Dense 为 5.81305394。MoE 在这次实验中没有带来改善。

Temporal Regime-MoE 已接入 Ranker 训练、judge、artifact 保存和无标签打分，专项测试为 41/41。当前证据只覆盖实现正确性，还没有多 seed、吞吐和样本外结果。实验顺序保持为 Dense V2、Temporal Regime-MoE、Backbone-MoE；前一阶段没有稳定增益时，不继续扩大训练规模。

跨股票上下文、Temporal Regime-MoE、实验登记和严格 artifact 校验均已完成代码接入。简单动量、反转和订单流因子也已有实现，但还缺同股票池、同标签、同成本的正式对照。下一步要验证的是订单流 embedding 相对这些简单基线的增量信息，而不是继续与随机基线比较。

本次全仓回归结果为 511 passed、2 skipped、1 xfailed，耗时 120.15 秒。两个跳过项都是缺少真实逐笔数据 fixture，说明单元测试覆盖较完整，但真实交易所数据的固定回归样本还需要补齐。

## 4. GPU 训练后端

已完成 Native Kubernetes、Kueue 和 Volcano 的功能对比：

- 9 个调度功能场景全部完成；
- Native K8s 四卡缩减矩阵 15/15 次运行成功；
- 已完成模型场景的排队中位数低于 0.7 秒；
- Multi-Pod 跨 Pod 通信使用 TCP Socket，未使用 IB/RDMA。

常规共享 GPU 任务可以使用 Kueue。固定进程数、需要同时启动的 DDP/MPI 任务可以试用 Volcano。Native Kubernetes 继续用于系统任务和隔离测试。

当前排队时间相对训练时间很短，后续性能优化会优先看训练代码、NCCL 通信和数据 I/O。

## 5. 目前这套系统能发挥什么作用

从现有结果看，这套系统不是只有框架，已经有三个可以实际使用的部分：逐笔数据可以稳定转成训练样本，数亿参数模型可以完成训练并恢复，股日 score 可以按统一格式批量交付。信号复核也表明 score 含有非随机的横截面信息。因此，它现在可以作为订单流研究平台，也可以向现有多因子或选股系统提供一项增量特征。

但它还不是一套已经完成收益验收的独立策略。当前主要差在后半段：训练日覆盖的市场状态有限；历史 Ranker 标签和实际执行时点没有完全对齐；正式 V2 数据尚未就绪；现有 2026 窗口已经参与过分析；交易成本、容量和时点股票池仍是研究级近似。

| 环节 | 当前状态 | 能发挥的作用 | 还缺什么 |
|---|---|---|---|
| 逐笔数据与订单簿回放 | V1 已大规模跑通，V2 因果回放代码完成 | 稳定生成训练数据，复现事件前后盘口 | 真实 V2 Pilot 和固定真实数据回归样本 |
| 预训练 | Dense230M、302M 和 Backbone-MoE 均有 checkpoint | 生成订单流表征，支持后续横截面建模 | 更多独立交易日、正式 validation/test 验收 |
| 股日 embedding | V1 已完成批量生成 | 为 Ranker 和其他模型提供统一输入 | 验证 V2 多尺度池化是否优于整日平均 |
| Ranker 与信号交付 | 61 日、60,846 条 score，12 项检查通过 | 可接入现有回测和多因子框架 | 按 T+1/T+2 标签重训，补正式时点股票池 |
| 回测与归因 | 已有 T+1/T+2、成本、换手和统计检验 | 做研究级信号筛选和方案对比 | 涨跌停、ST/新股、冲击成本、容量和完整风险模型 |
| 跨股票与 MoE | 代码和测试完成 | 为后续市场状态和横截面上下文实验提供基础 | 多 seed、吞吐、消融和新样本外结果 |
| GPU 后端 | 单节点 4 GPU 范围内已取得调度证据 | 支撑当前规模的数据处理和训练 | 非根盘 PVC、8 GPU/多节点、监控和故障恢复 |

现阶段最合适的判断是：系统已经证明“能生产数据、能训练、能交付，也能找到一定信号”，但还没有证明“单独使用就能稳定覆盖成本”。下一阶段的重点不应继续堆模型复杂度，而是用更严格、统一的实验把信号价值坐实。

## 6. 下一步

1. 先做至少 5 个真实交易日的 V2 数据 Pilot，检查回放行数、顺序、pre/post 盘口和 prefix causality，然后固定 vocab、manifest 和 validation plan。
2. 固定时点股票池、T+1/T+2 标签、成本和交易规则，在同一口径下重训 Ranker，并与动量、反转、订单流因子以及不使用预训练 embedding 的 Ranker 做成对比较。
3. 在 25M 模型上分别做单项消融，基线和每个候选都跑 3 个 seed，不同时改 Tokenizer、Loss、跨股票模块和 MoE。
4. 预留一段新的样本外时间窗口，在方案冻结后一次性评估 RankIC、ICIR、扣费收益、风险暴露和容量。
5. 只有在 25M 多 seed 和新样本外结果稳定后，再放大到 100M、230M 或引入 MoE。
6. 补齐 Kueue/Volcano 尚未完成的 10 个模型矩阵单元，每个单元至少跑 3 次。

## 7. 需要协调的事项

- 需要一段新的样本外时间窗口，专门用于最后验证。
- 需要经确认的非根盘 PVC。Dense230M 训练完成时本地磁盘剩余 8.1%，扩大训练前需先处理存储。
- 如果后续要跑 8 GPU 或多节点任务，需要确认物理拓扑、GPU 配额、NCCL 网络、监控和故障恢复方案。

## 8. 简短汇报版

“最近我主要做了数据处理、模型训练、信号交付和 GPU 后端测试。

数据方面已经处理 22 个交易日、5,105 只股票和 72.83 亿条事件，数据处理速度提高了 2.13 倍。Dense230M 已经完成 8 卡训练，跑了 5 万次 optimizer update 和 128.75 亿有效 token。同预算的 Backbone-MoE 参数多 28.5%，但 validation loss 没有比 Dense 好，所以后续会先保留 Dense 作为对照。

设计上，这次重点解决了三个问题。Token 不再只是增加字段，而是把缺失、未知和 padding 分开，用 token 加连续值双通道保留精度，并严格区分事件前后盘口；Loss 不再把不同难度的任务简单相加，而是按训练熵归一化，并给价格、成交量和时间间隔增加有序距离；MoE 则拆成轻量的市场状态适配和主干事件级专家两条路线，先验证 Dense 和 Temporal Regime-MoE，再决定是否投入成本更高的 Backbone-MoE。

信号方面已经生成 61 个交易日、6.08 万条 score，12 项质量检查都通过。补充复核后，Dense230M 在 59 个可计算交易日的平均 RankIC 是 0.0725，说明信号确实有一定排序能力；但固定低换手组合扣除双边各 15bp 成本后累计收益是 -0.60%，暂时还不能把它当成已经验证完成的独立策略。现阶段更适合把它接入现有选股框架，验证能否提供增量收益。

V2 的因果盘口、Tokenizer、Loss 和多尺度 embedding 框架已经搭好，但当前 25M 只跑了 5 步冒烟测试，真实数据还缺 9 个正式盘口字段。GPU 后端方面，Native K8s、Kueue 和 Volcano 的主要功能已经实测过。下一步先把 V2 数据、执行标签和简单因子对照做扎实，再进行 25M 多 seed 消融，只有稳定有效的改动才继续放大。”
