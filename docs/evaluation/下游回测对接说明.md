# QuantFM 下游回测对接说明

> 版本：2026-07-24
>
> 适用范围：内部研究、回测引擎联调与验收。
>
> 对外生产契约另见 [信号回测对接文档](信号回测对接文档.md)。

## 1. 先对齐边界

QuantFM 预训模型不直接输出委托或仓位。生产链路使用冻结 FM/Ranker 输出日频
`score`；收益标签、成交约束、组合、净值与风险归因都位于研究/回测侧。

| 我方生产责任 | 研究/回测责任 |
|---|---|
| 冻结 FM、股日 embedding 和 Ranker | PIT 交易日历与行情 |
| 三列 `date, symbol, score` | 明确的 entry/exit 收益定义 |
| score 时点和 artifact 元数据 | ST/新股/停牌/涨跌停/可成交性 |
| 无标签生产推理 | 组合构建、成本、冲击、风险与验收 |

本仓库提供一套可审计的研究实现，但它不是交易所/券商级生产回测引擎。

## 2. 2026-60d 的统计身份

2026 年 60 个信号日最初严格晚于 2025 年训练期，在当时是时序 OOS。但目前已经：

- 查看过 score、IC、净值、回撤和信号质量；
- 根据该结果定位了 Tokenizer、字段融合、Loss、股票间上下文和盘口设计问题；
- 用于制定 v2 改造方案。

因此这 60 日现在只能称为**架构验证/研究窗口**，不是 v2 的 untouched OOS。
可在该窗口做确定性回归、问题复现和研究排序，但最终泛化结论必须使用新的更晚时间段。

60 个交易日仅使日度序列可计算年化值，不代表年化收益已稳健。报告必须同时给出
原始日度统计、HAC t、block bootstrap、回撤、换手与成本敏感性。

## 3. 生产 score 契约

### 3.1 Schema

| 列 | 类型 | 约束 |
|---|---|---|
| `date` | string | 有效 `YYYY-MM-DD` |
| `symbol` | string | 6 位数字，左补零，不带 `.SH/.SZ` |
| `score` | float64 | 有限值；越大越看多 |

`quant_fm.signal.schema.validate_scores()` 要求列名和顺序**恰好**为
`date, symbol, score`，不允许空表、null、NaN/Inf 或重复 `(date, symbol)`。

`score(T)` 使用 T 日全天信息，在 T 日收盘后才可用。分数只保证同日截面可排序；
不应跨日比绝对值，也不应将其当成预测收益率或直接仓位。

### 3.2 生成命令

```bash
uv run python -m quant_fm.signal.generate \
  --embeddings /path/to/oos_embeddings.parquet \
  --ranker /path/to/ranker.pt \
  --ranker-metadata /path/to/ranker_metadata.json \
  --fm-checkpoint /path/to/best.pt \
  --vocab /path/to/vocab.json \
  --out-dir /path/to/delivery \
  --device cuda:0
```

输出目录对外只交付：

```text
delivery/
├── scores.parquet
└── signal_manifest.json
```

manifest 记录分数方向、可用时点、截面可比性、数据覆盖与 artifact 哈希。

## 4. Embedding 可选对接

只有回测方要自行训练 Ranker 或做因子融合时才交付 embedding：

```text
date | symbol | market | emb_0 ... emb_{D-1}
```

`D` 由 checkpoint 的 `d_model` 决定，不应在下游硬编码为 1024。一行一个股日，
`(date, symbol)` 必须唯一，embedding 必须与冻结 checkpoint、vocab 和池化配置同源。

## 5. 研究收益口径

`quant_fm.downstream.return_spec` 将信号日、建仓日、退出日和价格字段集中定义：

| 名称 | 建仓价 | 退出价 | 解读 |
|---|---|---|---|
| `close_t_close_t1` | T close | T+1 close | 旧口径/研究上限，对收盘后 score 不可执行 |
| `vwap_t_vwap_t1` | T VWAP | T+1 VWAP | 旧口径/研究上限，不可作为实盘结论 |
| `open_t1_close_t1` | T+1 open | T+1 close | 可交易日内近似 |
| `vwap_t1_vwap_t2` | T+1 VWAP | T+2 VWAP | 当前严格研究默认 |

任何报告都必须记录 `return_spec`，不允许只写“次日收益”。

## 6. Execution panel

### 6.1 构建 CLI

```bash
uv run python -m quant_fm.downstream.build_panel_from_minio \
  --from-embeddings /path/to/scores.parquet \
  --calendar-file /path/to/full_trading_calendar.txt \
  --return-spec vwap_t1_vwap_t2 \
  --out /path/to/execution_panel.parquet
```

`--from-embeddings` 是历史参数名，实际仅取输入文件的 `date/symbol`，可直接传 score。
也可用 `--signal-dates-file` 提供信号日。启用 `--return-spec` 时必须同时提供
`--calendar-file`，且日历需覆盖最后一个 exit 日。

`--allow-incomplete-horizon` 仅供排查，验收时禁用。

### 6.2 字段契约

| 类别 | 字段 |
|---|---|
| 键 | `date, symbol` |
| 时点 | `entry_date, exit_date` |
| 价格/收益 | `entry_px, exit_px, fwd_ret` |
| 口径 | `return_spec, entry_price_field, exit_price_field` |
| 信号日状态 | `is_st_at_signal, is_new_at_signal, is_halt_at_signal, limit_locked_at_signal, eligible_at_signal` |
| 建仓状态 | `is_halt_entry, limit_locked_entry, entry_fillable` |
| 退出状态 | `is_halt_exit, limit_locked_exit, exit_fillable` |

当前 `eligible_at_signal` 实现为非 ST、非新股、信号日非停牌；
`limit_locked_at_signal` 单独保留。建仓/退出日的停牌或全天涨跌停锁定使对应
`entry_fillable/exit_fillable=False`。

`fwd_ret = exit_px / entry_px - 1`。它是报价区间收益，可成交性另由 fillable 字段处理。

### 6.3 防止执行日补选

目标持仓只能使用 `score(T)` 和 `eligible_at_signal(T)`。
`entry_fillable`/`exit_fillable` 只能决定订单成交或拒绝。买入失败后保留现金，
不得根据已知的执行结果补选低排名标的。

仓库当前的重叠日频模拟在每个 interval 的 `entry_date` 调仓，买卖均检查当前行的
`entry_fillable`。`exit_fillable` 不会提前决定本期持仓或收益，避免读取未来退出日状态。

## 7. 严格 score 研究评估

### 7.1 CLI 与 Make

```bash
uv run python -m quant_fm.downstream.run_score_evaluation \
  --scores /path/to/frozen_scores.parquet \
  --panel /path/to/execution_panel.parquet \
  --out-dir /path/to/evaluation \
  --factors /path/to/pit_factors.parquet \
  --quantile-groups 10 \
  --top-k-grid 20,50,100,150,200 \
  --rebalance-grid 1,5 \
  --smoothing-grid 1,3 \
  --cost-bps-grid 0,15,30
```

```bash
make research-score \
  SCORES=/path/to/frozen_scores.parquet \
  PANEL=/path/to/execution_panel.parquet \
  OUT_DIR=/path/to/evaluation

CALENDAR=/path/to/full_calendar.txt \
RETURN_SPEC=vwap_t1_vwap_t2 \
make research-oos2026
```

`research-oos2026` 调用 `quant_fm/scripts/run_oos2026_research.sh`，可通过
`OOS_WORKDIR, SCORES, CALENDAR, RETURN_SPEC, RESEARCH_DIR, PANEL` 覆盖默认路径。

默认评估会逐键、逐标的检查 horizon：全部 score 键必须命中 panel；所有信号日可投资
标的必须有有限 `fwd_ret`；每日有效横截面不少于 3 且至少产生一期有限 IC。报告分别记录
`join_coverage` 和 `label_coverage`，非有限统计量序列化为 JSON `null`。

### 7.2 指标

- 日度 Spearman RankIC、均值、标准差、ICIR 和正 IC 比例；
- 朴素 t 与 Newey-West/HAC t；
- 5 日移动块、2000 次重采样的均值 95% bootstrap 区间；
- 逐日分位组收益；
- Top-K、调仓频率、score 平滑和成本网格；
- 主组合粗收益、成本、净收益、NAV、现金、换手、拒单和回撤；
- 相对可投资股票等权基准的 active return 与 information ratio；
- 可选 `factor_*` 风险暴露和中性化收益 IC。

### 7.3 输出

```text
evaluation/
├── metrics.json
├── evaluation_manifest.json
├── daily_ic.parquet
├── quantile_returns.parquet
├── topk_grid.parquet
├── portfolio_daily.parquet
├── holdings.parquet
└── trades.parquet
```

有 `factor_*` 时另写 `exposure_daily.parquet` 和 `daily_neutralized_ic.parquet`。
manifest 保存 score/panel/factors 路径和 SHA-256，以及面板中的 return spec 元数据。

## 8. 组合模拟 API

```python
from quant_fm.downstream.portfolio_simulator import (
    CostConfig,
    PortfolioConfig,
    simulate_buffered_topk,
)

result = simulate_buffered_topk(
    scores,
    execution_panel,
    portfolio=PortfolioConfig(
        candidate_top_k=150,
        target_holdings=100,
        entry_rank=80,
        exit_rank=180,
        rebalance_interval=1,
        score_smoothing_days=3,
        max_turnover=1.0,
    ),
    costs=CostConfig(
        buy_bps=15.0,
        sell_bps=15.0,
        stamp_duty_bps_sell=0.0,
    ),
)
```

`PortfolioSimulationResult` 含：

- `daily`：逐日收益、成本、NAV、现金、换手和失败订单数；
- `holdings`：逐日持仓、权重、排名、平滑 score 和收益；
- `trades`：买卖、是否成交和拒单原因；
- `summary`：天数、累计收益、日均/波动、年化 Sharpe、回撤、换手和总成本。

买入不可成交时不补选，目标仓位未满的部分按现金收益 0 计算。

`quant_fm.downstream.backtest_topk` 是保留的简化历史参考实现；对严格 execution panel 的新研究
应优先使用 `simulate_buffered_topk()` 和 `run_score_evaluation`。

## 9. 风险归因 API

因子表主键为 `date, symbol`，自动发现以 `factor_` 开头的数值列：

```python
from quant_fm.downstream.risk_attribution import (
    portfolio_exposures,
    residualize_returns,
)

exposure_daily = portfolio_exposures(result.holdings, factors)
neutralized = residualize_returns(execution_panel, factors)
```

`portfolio_exposures()` 按非空因子的持仓权重归一后汇总日度暴露。
`residualize_returns()` 逐日用常数项 + 因子做 OLS，默认返回 `neutralized_ret`；
每日有效样本必须多于因子数 + 1。

## 10. Paired IC / OOS 比较

对新旧 FM、池化或 Ranker 的比较必须是 paired，不能将两个不同日期/股票池的
均值 IC 直接相减。

当前 `run_score_evaluation` 一次只支持一份 score，没有 `--paired` CLI。正确流程：

1. 冻结 execution panel、return spec、股票池、网格和成本；
2. 校验 baseline/candidate 的 `(date, symbol)` 键集合一致；
3. 两个 score 各自运行评估，保留各自 manifest；
4. 按 `date` 内连接 `daily_ic.parquet`，构造
   `delta_ic = ic_candidate - ic_baseline`；
5. 对 `delta_ic` 运行 `ic_statistics()` 和 `block_bootstrap_mean_ci()`；
6. 同时对照成本后收益、换手、回撤、拒单和风险暴露。

```python
import polars as pl

from quant_fm.downstream.evaluate import (
    block_bootstrap_mean_ci,
    ic_statistics,
)

base = pl.read_parquet("baseline/daily_ic.parquet").rename({"ic": "base_ic"})
new = pl.read_parquet("candidate/daily_ic.parquet").rename({"ic": "new_ic"})
paired = base.join(new, on="date", how="inner").with_columns(
    (pl.col("new_ic") - pl.col("base_ic")).alias("delta_ic")
)
delta = paired.select(pl.col("delta_ic").alias("ic"))
delta_stats = ic_statistics(delta)
delta_ci95 = block_bootstrap_mean_ci(delta["ic"].to_numpy())
```

2026-60d 可用于这种配对开发比较，但结果不是 v2 最终 untouched OOS 证据。

## 11. 历史 embedding Judge

```bash
uv run python -m quant_fm.downstream.run_judge \
  --workdir /path/to/workdir \
  --checkpoint /path/to/best.pt \
  --panel /path/to/daily_panel.parquet \
  --emb-dir /path/to/embeddings \
  --epochs 30 \
  --device cuda:0 \
  --top-k 50 \
  --seed 42
```

`run_judge` 用 train 拟合、val IC early stop/恢复最佳 epoch，再计算 train/val/test、随机对照和 CPCV。
输出在 `<workdir>/downstream/` 下的 `runs/*.json, latest.json, history.jsonl`。
该链路读取标签并重训 Ranker，是 research-only；对冻结交付 score 的验收应使用第 7 节。

## 12. 已知限制

1. L2 快照无法可靠恢复官方 ST/新股日历，当前字段默认 `False`。
2. `limit_locked` 是根据成交后观测价格全天锁定的近似，不是逐笔排队成交模型。
3. 当前组合模拟为日频等权近似，未完整实现 A 股 T+1 卖出约束、冲击、排队和容量。
4. 默认成本是固定 bps，印花税默认为 0，必须按研究期间和市场替换。
5. 等权基准和原始 `fwd_ret` 含市场 beta；应辅以 long-short/风险中性化和暴露归因。
6. 任何参数网格都构成多重尝试；不得根据架构验证窗口中的最佳点再宣称同窗口 OOS。

## 13. 联调 Gate

| 优先级 | 检查 | 通过条件 |
|---|---|---|
| P0 | 生产 schema | 列恰好为 `date, symbol, score` |
| P0 | 主键/值 | 键唯一，无 null/NaN/Inf，symbol 为 6 位 |
| P0 | 时点 | 不用 `score(T)` 做 T 日盘中/收盘前成交 |
| P0 | 收益口径 | 报告显式记录 return spec 与日历 horizon |
| P0 | 完整性 | 不允许缺少最后信号日 exit 行情 |
| P1 | 覆盖 | score-panel join coverage 与每日股票数无异常 |
| P1 | 执行 | 选股不读 fillable，拒单不补选，账本可追溯 |
| P1 | 统计 | IC/HAC/bootstrap/分组/成本网格同时完整 |
| P1 | 对照 | A/B 键集合相同，使用 paired daily IC |
| P2 | 泛化 | 新的 untouched OOS 在任何查看前冻结全部设置 |
