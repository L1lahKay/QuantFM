## 3. v1 / v2 隔离原则

v1 继续作为稳定基线，不迁移、不覆盖：

```text
schema:     cn_l2_v1
vocab:      quant_fm.tokenizer.vocab.Vocab
special:    PAD=0, N_SPECIAL=1
dataset:    quant_fm.pretrain.dataset.EventWindowDataset
fusion:     legacy_sum
checkpoint: vocab_version=1.0 / fm_artifact_version=1.0
```

v2 使用完全独立 artifact：

```text
schema:     cn_l2_v2
vocab:      quant_fm.tokenizer.vocab_v2.VocabV2
special:    PAD=0, UNK=1, NA=2, BOS=3, EOS=4, SESSION_BREAK=5
dataset:    quant_fm.pretrain.dataset_v2.EventWindowDatasetV2
checkpoint: vocab_version=2.0 / fm_artifact_version=2.0
directory:  runs/*_v2 或 runs/v2_*
```

禁止：

- 把 v2 特殊 token 写回 v1 `vocab.py`；
- 用 v1 vocab 加载 v2 checkpoint，或反向混用；
- 在原 `medium_300m` 目录覆盖 v1 vocab/token/checkpoint；
- 仅凭列名相似就跳过 schema、hash 和 FieldSpec 顺序校验。


这张图中，raw replay 到 `cn_l2_v2` 的自动编排、learned aggregator/Temporal MoE 的训练

## 5. 订单簿正确性与因果状态

### 5.1 撤单一致性

`quant_fm` 的 SH/SZ 构建器共用 `MatchingEngine`。本轮修改：

- `cancel_order()` 从 bid/ask 对应 price-level deque 中物理删除订单；
- 删除空价格档；
- 撤销中间订单不改变同价位剩余订单的 FIFO；
- `_purge_level_front()` 同时检查 quantity 与活动订单索引；
- `_compact_book()` 清理 quantity≤0 或已脱离 `orders` 的 stale order。

回归覆盖：

```text
tests/test_order_book_cancel_consistency.py
tests/test_book_state_causality.py
```

### 5.2 `BookState` API

实现文件：`order_book/pylob/book_state.py`。

```python
from pylob import (
    capture_book_transition,
    iter_book_state_transitions,
    snapshot_book_state,
)
```

`BookState` 保存：

```text
valid / bid1 / ask1 / bid_qty_1 / ask_qty_1
bid_depth_5 / ask_depth_5 / bid_depth_10 / ask_depth_10
spread_ticks
imbalance_1 / imbalance_5 / imbalance_10
microprice_delta_ticks
```

`valid` 表示双边报价存在；单边簿仍保存可用深度与 imbalance。

统一时点定义：

```text
pre_event_state(t)
  → apply event(t)，且 callback 只能处理当前事件
post_event_state(t)
  → 可附在 event(t) 上用于预测 event(t+1)
```

最小调用：

```python
transition = capture_book_transition(
    book,
    lambda: apply_event(current_event),
    tick_size=100,
)
```

### 5.3 当前集成限制

`book_state.py` 是显式 helper，不会拦截或自动记录 `MatchingEngine` 的所有调用。
现有 `build_clean_dataset`、`clean_day_fast.py` 和 `canonicalize_clean_dir()` 仍走 v1
导出。生成 v2 数据时必须：

1. 在 raw replay 循环中显式调用 capture；
2. 保证事件、transition、event price 三者逐行一一对应；
3. 使用交易所 sequence，而不是可能包含接收延迟的 `local_time` 排序；
4. 在写 v2 前执行 prefix causality 与行数检查。

未完成这一步时，不得给旧 `events.parquet` 添加版本标签并冒充 `cn_l2_v2`。

## 7. Tokenizer v2

### 7.1 冻结字段声明

`quant_fm/tokenizer/field_spec.py` 提供：

```python
FieldSpec
DEFAULT_FIELD_SPECS_V2
BOOK_FIELD_SPECS_V2
FULL_FIELD_SPECS_V2
```

`FieldSpec` 冻结：字段逻辑名、source、kind、请求 bin 数、适用事件、input/target
用途和 missing-token 契约。token/scalar 列名由它派生：

```text
categorical/context → tok_<name>
ordinal/binned continuous → tok_<name>_bin
ordinal/continuous → val_<name>
```

默认 v2 字段移除了确定性 `event_source`、伪 `order_type` 和逐事件 `board`。
`session` 保留输入，但默认不作为 next-event target。

### 7.2 独立特殊 token

`quant_fm/tokenizer/vocab_v2.py` 固定：

```python
PAD_ID = 0
UNK_ID = 1
NA_ID = 2
BOS_ID = 3
EOS_ID = 4
SESSION_BREAK_ID = 5
N_SPECIAL = 6
```

连续缺失映射到 `NA_ID`。对应 `val_*` 缺失位置写 0，但模型同时看到独立 NA token，
因此真实数值零与缺失不再混淆。

### 7.3 全流分层拟合

`fit_vocab_v2()` 会遍历完整训练集三次：

1. 全流统计类别、finite/missing、mean/std/min/max 和分层样本数；
2. 按 `date × exchange × board × evt_type` 执行确定性 priority reservoir；
3. 在冻结边界上统计完整训练流的精确 occupancy。

重复分位边界直接合并，因此 `actual_n_bins` 可小于 `requested_n_bins`，不会构造伪
linspace 补齐。vocab 保存 occupancy、missing rate、normalizer、fit dates、采样方法、
seed 和分层信息。

日期审计不是调用方可随意填写的标签：参与拟合的 parquet 必须至少提供非空 `date` 值；
实现会从实际读到的 shard 收集 `observed_dates`。若显式传入 `fit_dates`，其集合必须与
`observed_dates` 完全一致，任一 declared-only/observed-only 日期都会 fail fast；artifact
始终写入排序后的真实 `observed_dates`。这可阻止用声明日期掩盖实际参与拟合的 shard，
但调用方仍需保证传入路径本身只属于训练切分。

### 7.4 拟合和 token 化 API

v2 当前是 Python API，尚无完整批量数据生产 CLI：

```python

from quant_fm.tokenizer.fit_bins_v2 import fit_vocab_v2

    assert_no_leakage_v2,

```

## 8. 字段融合与连续双通道

实现文件：

```text
quant_fm/pretrain/field_fusion.py
quant_fm/pretrain/model.py
```

实际配置结构：

```python
@dataclass(frozen=True, slots=True)
class FieldFusionConfig:
    method: str = "legacy_sum"
    field_dim: int = 32
    field_dropout: float = 0.0
    input_norm: bool = True
```

支持四种方法：

- `legacy_sum`：v1 兼容路径；字段 embedding 均为 `d_model`，直接相加；
- `scaled_sum`：按字段权重 L2 范数缩放，并可做 RMSNorm；
- `gated_sum`：每字段可学习 sigmoid gate、field dropout、缩放和 RMSNorm；
- `concat_mlp`：每字段 `field_dim` 表示拼接后经两层 MLP 投到 `d_model`。

`field_dropout` 每次 forward 生成一个字段 mask，至少保留一个字段，只在 train 模式
生效。它不是 PAD/NA，二者语义仍由 token 决定。

连续双通道由 `OrderFlowFMConfig.scalar_fields` 管理：

```text
ordinal token embedding + Linear(val_*, bias=False)
```

`standalone_scalar_fields` 支持没有 token 同伴的纯标量字段。当前字段融合对所有字段
使用同一个 `field_dim`；设计稿中按 categorical/ordinal/context 设置不同维度的接口
尚未实现。

v2 配置中的 `categorical_dim` 由训练 parser 兼容映射到 `field_dim`：

```yaml
model:
  field_fusion:
    method: gated_sum
    categorical_dim: 32
    field_dropout: 0.10
    input_norm: true
```

### 9.2 Loss v2

`quant_fm/pretrain/heads.py` 已实现：

```python
TargetSpec
target_specs_from_config(...)
next_event_loss_v2(...)
```

目标有效位置组合：

```text
attention_mask[t] & attention_mask[t+1]
& target not in ignore_ids (v2 默认 PAD/NA)
& applicable_event_ids（若配置）
& mask_<target>（若存在）
```

每目标 Loss：

```text
raw CE / frozen train unigram entropy
  + ordinal_weight × normalized expected-bin smooth-L1
```

再乘静态 task weight。全 NA 或全不适用 target 保留计算图并返回零，不产生 NaN。

当前配置：

```yaml
loss:
  normalize_by_train_entropy: true
  targets:
    tok_evt_type: {type: ce, weight: 1.0}
    tok_side: {type: ce, weight: 1.0}
    tok_price_bin: {type: ordinal_ce, weight: 1.0, ordinal_weight: 0.5}
    tok_volume_bin: {type: ordinal_ce, weight: 0.5, ordinal_weight: 0.25}
    tok_delta_t_bin: {type: ordinal_ce, weight: 0.5, ordinal_weight: 0.25}
```

v2 训练如果缺少显式 `loss.targets` 会 fail fast。v1 配置没有 `loss.targets` 时继续用
原等权 next-event CE，不改变旧 checkpoint 的训练语义。

尚未实现：未来 microprice/mid/OFI/volatility 辅助目标、soft-neighbor ordinal target、
条件联合 head 和 T+1 收益 fine-tuning。这些仍是后续候选，不属于当前已完成代码。

## 11. Checkpoint 与 artifact 校验

### 11.1 训练计数与运行语义

`TrainState` 分别记录：

```text
micro_step             每 rank 已完成反向的 micro-batch 数
update_step            成功参数更新数
samples_seen           成功 update 后跨 rank 汇总的窗口数
non_pad_tokens_seen    成功 update 后跨 rank 汇总的 attention_mask.sum()
best_val / best_update_step
```

LR、日志、验证和 checkpoint 都按 `update_step` 驱动。FP16 GradScaler 因 overflow 跳过
参数更新时，只保留已经发生的 `micro_step`，不会增加 update/sample/token。终止条件是
`max_update_steps` 与 `max_train_tokens` 的 OR；token 上限最多越过一个成功的全局 update。
token-budget-only 配置必须显式给 `optim.lr_schedule_steps`，用固定 update horizon 计算余弦
LR，不能让 horizon 随当前 step 漂移。

`ShardAwareDistributedSampler` 先按 parquet shard 聚簇，epoch 级打乱 shard 和 shard 内
window，再把等窗口数的连续片段分给 rank。它改善文件局部性，但尚未按 non-pad token 或
短尾长度均衡；`drop_last=True` 会丢弃不足所有 rank 的尾部。DataLoader 已启用可配置的
`persistent_workers/prefetch_factor`、pinned memory 与 non-blocking device copy。

### 11.2 RoPE、attention 与 FFN

- RoPE cache 按 `(device.type, device.index, dtype)` 惰性复用，至少覆盖
  `max(current_length, max_seq_len)`，不进入 `state_dict`；
- 无 padding batch 使用 `scaled_dot_product_attention(attn_mask=None, is_causal=True)`；
  含 padding 时使用显式 causal + key mask；
- Dense SwiGLU 支持显式 `ffn_hidden`，缺省才使用 `int(d_model * ffn_mult)`；
- cache/fast path 已有数值回归，真实 GPU token/s、显存和 compile/fused optimizer 仍待测。

### 11.3 checkpoint 角色和兼容校验

`quant_fm/pretrain/train.py` 会根据 vocab 类型构造 v1/v2 dataset 和模型。所有 v2
checkpoint 保存：

```text
fm_artifact_version=2.0
schema_version
vocab_version=2.0
vocab_sha256
field_specs（冻结顺序）
field_fusion / scalar_fields / standalone_scalar_fields
continuous_normalizers
target_specs
book_state_timing
context_horizon
pooling_version
backbone_moe
model_state / train_state
```

文件角色不同：

| 文件 | 状态 | 用途 |
|------|------|------|
| `step<update>.pt` | model + optimizer + scaler + TrainState | 定期完整续训 |
| `final_resume.pt` | model + optimizer + scaler + TrainState | 正常结束后的完整续训 |
| `best.pt` | model + metadata + TrainState | 最优评估/推理，不可 resume |
| `final.pt` | model + metadata + TrainState | 最终评估/推理，不可 resume |

v2 加载必须提供 vocab：

```python
model = load_checkpoint(
    checkpoint_path,
    device,
    vocab_path=vocab_v2_path,
)
```

loader 校验 artifact version、schema、vocab SHA-256、FieldSpec 和 input/target 顺序。v2
resume 进一步逐项校验 field sizes、宽深/head/FFN/dropout/RoPE、fusion/scalar/normalizer、
book/context/pooling、Backbone-MoE 和 target specs。训练入口拒绝使用 `best.pt/final.pt`
resume；`--resume auto` 只在 `step*.pt`/`final_resume.pt` 中选择，并优先编号最大的定期点。
继续正常结束的 run 应显式指定 `final_resume.pt`。v1 checkpoint 缺少新字段时使用默认
`legacy_sum`，不要求 v2 vocab。

当前 checkpoint 仍未保存 DataLoader 精确游标和全部 RNG 状态，因此 `--resume` 是
工程级恢复，不保证与不中断训练逐字节一致。

## 13. 跨股票上下文

已新增：

```text
quant_fm/cross_asset/clock_grid.py
quant_fm/cross_asset/context_pool.py
quant_fm/cross_asset/dataset.py
quant_fm/cross_asset/model.py
```

实现边界：不接受全市场异步 raw event，只接受单股已经汇总的 interval embedding。

### 13.1 同步时钟

`clock_interval_id()` / `add_clock_interval()` 默认映射到 5 分钟 interval，上午/下午
各自编号，不跨午休；集合竞价可作为 interval 0，非交易时段为 -1。

### 13.2 PIT 行业与 leave-one-out

`join_pit_industry()` 使用严格 backward as-of join：

```text
industry effective_time < prediction_time
```

相等时刻不允许生效。`align_interval_embeddings()` 生成 `[T,N,D]`、`active_mask` 和
PIT `industry_id`；缺失位置为零且 mask=False。

`build_synchronous_context()` 以 O(N) sum/count 生成：

```text
market
industry_leave_one_out
own_minus_market
own_minus_industry
industry_has_peer
```

行业上下文严格扣除自身，无同行业 peer 时返回零。

### 13.3 线性复杂度模型

`LinearCrossAssetModel` 的输入为 `[T,N,D]`，先编码 own/market/industry/residual
上下文，再沿时间轴对每只股票运行因果 GRU。声明：

```python
cross_section_complexity = "O(T*N*D)"
accepts_raw_events = False
```

它没有 dense N² attention，也没有 raw-event API。

### 13.4 当前集成限制

跨股票模块目前没有接入：

- FM 预训练循环；
- `extract_hidden.py` 标准输出；
- Ranker 默认 dataset/config；
- `run_judge` 或生产 score 入口。

因此它是研究基础设施，不是当前生产评分的一部分。PIT 行业历史表、interval
embedding 构建、训练目标、checkpoint 和评分适配仍需实现。

## 14. Regime-MoE 与顶部 Backbone-MoE

### 14.1 Temporal Regime-MoE

`quant_fm/moe/temporal_moe.py` 已实现 residual + shared expert + Top-K routed experts：

```python
output = TemporalRegimeMoE(hidden_dim, regime_feature_dim, config)(
    hidden,
    regime_features,
)
# output.hidden / output.router / output.auxiliary_loss / output.overflow_rate
```

`RegimeIntradayModel` 可将其接在 `IntradayAggregator.full_day_summary` 之后，但目前没有标准
dataset、训练 loop、embedding CLI 或 score 入口。`RegimeFeatureNormalizer` 可保存训练期
mean/scale 和 `fit_end`，`RegimeFeatureSpec` 可声明 `availability_lag`；当前 API 只记录这些
审计信息，不会替调用方执行日期过滤、lag 或 PIT as-of join。

### 14.2 Backbone-MoE

`BackboneMoEConfig.layer_indices` 指定把哪些 Transformer 块的 Dense SwiGLU 替换成
`SparseMoEFeedForward`。`OrderFlowFM` 会把 `attention_mask` 传给 MoE，只路由有效 token，
并将各 MoE 层的 router auxiliary loss 求和加入训练目标。`config_v2_backbone_moe.yaml`
当前选择顶部 4 层、4 routed experts、Top-1 和 shared expert。

训练模式按 `capacity_factor` 裁剪 assignment，overflow 时存在 batch 范围的容量竞争；
评估/推理模式不裁剪，`overflow_rate=0`，已有 padding invariance 和低 capacity 下的
batch-size independence 回归。该设计避免推理结果随 batch 容量变化，但真实训练中的
overflow、train/eval dispatch 差异、router collapse、FSDP 吞吐和下游效果都没有验证。

### 14.3 telemetry 与 artifact 边界

`summarize_moe()` 只提供 expert fraction、归一化 entropy、平均 top-1 probability 和
overflow rate。当前训练 loop 仅写 `train/moe_aux`，没有自动调用 telemetry，也没有
by-date/by-regime、逐层 overflow 或 expert 输出相似度。

`save_regime_moe_artifact()` 保存 `regime_moe_v1`、model state、Regime 配置、feature
normalizer、`data_cutoff` 和 `base_model_sha256`；`load_regime_moe_metadata()` 只验证版本并
返回 payload。它尚未保存/重建 aggregator 配置、hidden/feature 维度或完整下游模型，不能
视为一键生产 loader。所有这些模块的准确状态都是“代码已实现、实验/生产未验证”。

## 18. 推荐执行顺序

### Stage 0：接通数据并做 smoke

1. 在 SH/SZ raw replay 循环显式接入 `capture_book_transition()`；
2. 生成少量 `cn_l2_v2`，执行行数、prefix causality、空簿/单边簿检查；
3. 用 `FULL_FIELD_SPECS_V2` 拟合仅训练日 vocab；
4. 生成少量 token，检查 coverage、NA、UNK、actual bins；
5. 建 v2 manifest 和固定 validation plan；
6. 单 batch forward/backward、checkpoint roundtrip、embedding smoke。

### Stage 1：无需重训的 pooling 对照

在同一 v1 checkpoint 上对比：

```text
mean
lastk_mean(last_k=256/1024)
multi_scale
```

保持 Ranker、日期、seed、收益标签、成本和风险处理不变，先验证原有 pooling bug 修复
及固定多尺度是否有增量。

### Stage 2：25M 单因素消融

每次只改变一类因素：

| 实验 | 唯一变化 |
|------|----------|
| A0 | v1 baseline |
| A1 | tokenizer v2，不加盘口 |
| A2 | `scaled_sum` |
| A3 | `gated_sum + field_dropout` |
| A4 | `concat_mlp` |
| A5 | entropy-normalized CE |
| A6 | ordinal auxiliary |
| A7 | 紧凑盘口字段 |

不要第一轮同时改 tokenizer、fusion、loss 和 book，否则无法归因。

### Stage 3：100M 复验

只让 Stage-2 winner 晋级。至少运行 3 seeds，并统一：

- 训练 token 数和验证清单；
- frozen embedding 提取方式；
- Ranker 配置和 seed；
- 标签、成本、Top-K 和风险中性化；
- 同日 paired IC 差与 bootstrap/Newey-West 检验。

### Stage 4：learned pooling、Temporal Regime-MoE 与 cross-asset

固定最佳单股 FM 后分别接入：

1. chunk-summary dataset + `IntradayAggregator`；
2. train-only/PIT regime features + `TemporalRegimeMoE` + telemetry；
3. 5 分钟 interval embedding + PIT industry + `LinearCrossAssetModel`。

三者各自单独过 OOS 增量门槛后再组合，最后才考虑接生产评分。

### Stage 5：Backbone-MoE

只有轻量 Regime-MoE 多 seed 晋级后才运行 `config_v2_backbone_moe.yaml`。固定有效 token、
active FFN hidden、验证窗口和 Ranker seeds，额外报告训练期 overflow、expert fraction、
router entropy、non-pad tokens/s、显存与 FSDP checkpoint 恢复。代码可运行不等于获准晋级。

## 19. 晋级和 OOS 规则

建议门槛：

### 25M 筛选

- 两个 seed 的验证 ΔRankIC 均为正；
- 平均绝对提升至少 0.005；
- paired daily IC bootstrap 80% 区间下界大于 0；
- normalized NLL 不恶化超过 1%；
- 无 NaN、token 坍缩、coverage 异常和因果泄漏。

### 100M 复验

- 至少 2/3 seeds 的 ΔRankIC 为正；
- 平均 ΔRankIC ≥ 0.005；
- 同日 IC 差 Newey-West t ≥ 2；
- 分组单调性和扣成本净收益改善；
- 换手增幅不超过 10%；
- 吞吐下降不超过 10%；
- 显存增幅超过 15% 时必须有更强收益证据。

### 最终 untouched OOS

- 架构、vocab、loss、pooling、Ranker 和风险规则全部冻结后才能开始；
- 当前已分析 2026-60d 不再算 untouched；
- 最好扩展到至少 252 个交易日；
- 同时报告 raw/risk-neutral IC、RankIC、分组单调性、Top-K 扣成本收益、换手和
  风险归因，不能只报告年化收益。

- 撤单一致性与盘口因果性测试通过；

> **真实因果盘口状态 + 有序连续编码 + 可解释多任务 Loss + 正确分层时间池化 +
